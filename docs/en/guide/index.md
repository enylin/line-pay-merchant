# Introduction

line-pay-merchant is a library for the LINE Pay Online API **V4** on Node.js back ends. It takes care of signing, transport and types, and it treats "the outcome of a payment is uncertain" as a first-class case.

::: warning Pre-release
1.0 is in alpha. The official V4 reference was not available when this was written. The paths and fields follow LINE Pay's V3 API and what independent V4 clients and the 0.9 documentation agree on, and none of it has been run against the V4 sandbox yet; the open points are marked `TODO(v4-spec)` in the source. Before going live, run the whole flow in the sandbox, including a second `confirm` of the same transaction.

If you use V3, stay on 0.9.x. See the [migration guide](/en/migration/from-0.9).
:::

## What it solves

**1. You do not sign requests yourself.** The `X-LINE-Authorization` header of every request is generated by the library (HMAC-SHA256 with Web Crypto), and it signs _the exact text that is sent_, so serialisation differences cannot produce a wrong signature.

**2. Transaction IDs are not mangled.** LINE Pay transaction IDs have 19 digits, which is more than JavaScript can represent exactly (2^53). A plain `JSON.parse` silently changes the last digits. This library turns every integer outside the safe range into a string while parsing, so the `transactionId` in a response is always right.

**3. A timeout is not a failure.** This is the important one. When `confirm` times out, the connection is cut, or LINE Pay answers "duplicate", you do not know whether the customer was charged. Most libraries throw a generic error here and leave you to guess. This one:

- marks every error with an `outcome`: `not-sent` (it provably never left), `unknown` (it may have been processed), `rejected`;
- by default retries only what is provably safe: requests that never left (any operation), and reads whose outcome is unknown; a request that moves money is **not re-sent** after an unknown outcome;
- offers `client.reconcile()`, which looks at the payment details and answers `applied`, `not-applied` or `indeterminate`, with its evidence.

See [Unknown outcomes and reconcile](./unknown-outcome).

## What it does not do

- It does not store orders, schedule jobs or render pages. That belongs to your application; the [recipes](/en/recipes/) show how to combine it with them.
- It does not decide amounts. The amount of `confirm` must come from your database, not from the URL (see [Security](./security)).
- It is not the LINE Pay documentation. For the meaning of each field, read the [official documentation](https://developers-pay.line.me/).

## Requirements

- Node.js 22 or later. Environments that have `fetch` and Web Crypto (Bun, Deno, Cloudflare Workers) should work, but only Node.js is tested.
- A LINE Pay Channel ID and Channel Secret Key. For development use a [sandbox account](https://developers-pay.line.me/sandbox).
